# Solomonoff Loop（所罗门诺夫循环）

> **一个让大模型拥有「可验证、可累积、可审计」自我进化能力的框架——把模型的隐性知识「结晶」成可执行程序，再以这些程序作为它自己的真值锚点。**

## 一句话说明问题

每一次试图让大模型「自己改进自己」的尝试，都以同一种方式失败：**这个循环的上限，取决于它用来攀爬的那个信号，而这个信号往往是一个披着外衣的 LLM。** 自奖励模型会过度奖励自己高置信度的错误（**自我确认循环**）；用自身输出训练自己会丢失分布尾部，直到模型坍缩成重复的「貌似合理」（**模型坍缩**，可证明为熵衰减）；课程提议者会收敛到「恰好满足奖励」的窄带上（**多样性坍缩**）。而由于几乎没人跑冻结对照，很多被报道的「自我改进」其实是测量伪影，而非真实能力增长。

根本原因始终是同一个：**评估器要么是「学出来的」，要么是「自我指涉的」，要么干脆「不存在」。** Solomonoff Loop 就是针对这个根本原因提出的方案——而不是去微调优化器。

## 一句话说明方案

让模型反复把自己学到的隐性知识**压缩**成一个显式的、可执行的、可读的**程序层**（我们称之为**晶体 Crystal**）。晶体里的每一个程序都经过一个**机械验证器**（我们称之为**铁砧 Anvil**）——执行器、证明检查器、或保留数据匹配——**绝不是一个 LLM**。一旦验证通过，晶体就同时成为四样东西：**(a)** 阻止坍缩的外部接地，**(b)** 模型可以内省的、可读的自我模型，**(c)** 不会坍缩的课程，**(d)** 一个内置的冻结对照，让「进步」可以被**审计**，而不是被**声称**。

名字来自 **Solomonoff 归纳**：排序信号不是模型自己的似然（那是循环的），而是**描述长度**——「找到解释数据的最短程序」。一个最短程序定义了**整个**分布，包括有限采样丢失的尾部。正是这一处替换，把一个自我指涉的循环变成了一个有接地的循环。

```
        ┌──────────────────────────────────────────────────────┐
        │                                                      │
        ▼                                                      │
  ┌──────────┐  1. 提议   ┌──────────────┐  2. 验证    ┌─────────┐
  │ 提议者     │ ────────► │ 候选程序      │ ─────────► │  铁砧    │
  │  (LLM)    │           │              │            │ 机械验证器 │
  └──────────┘           └──────────────┘            └────┬────┘
        ▲                                                  │ 仅通过者保留
        │                                                  ▼
  ┌──────────┐  5. 接地/   ┌──────────────────────────────┐
  │ 蒸馏回权重 │ ◄───────── │  晶体（已验证程序库，随时间增长） │
  └──────────┘  内省      └───────────────┬──────────────┘
                                          │ 3. 按描述长度排序
                                          ▼
                                   ┌──────────────┐
                                   │  引导者 (LLM)  │  反平凡 +
                                   └──────────────┘  规范接地审计
```

## 为什么它与众不同

| 现有方法 | 如何攀爬 | 为何停滞 |
|---|---|---|
| 自奖励（Yuan et al. 2024） | LLM 评判自己的输出 | 裁判与策略共享同一权重 → 自我确认循环 |
| 自对弈（SPIN、DNO、R-Zero） | 与过去的自己对抗 | 语言中没有对手；课程会收窄 |
| RLVR（DeepSeek-R1） | 机械校验（代码能跑、答案匹配） | 有效，但局限于可验证领域 |
| Harness 工程（Darwin Gödel Machine、Lilian Weng） | 改写脚手架，权重冻结 | 模型本身不变；无法累积 |
| **Solomonoff Loop** | **对「不断增长的、压缩的、可读的程序层」做机械校验** | **—（这正是本提案）** |

核心论断是一个不对称性：

> **合成错误会被「检测并丢弃」（程序验证失败 → 扔掉）；而评估器错误会被「静默吸收」（坏奖励 → 被强化）。弱的合成器只会拖慢循环；弱的评估器会腐化循环。因此唯一不可恢复的失败模式是评估器——而本框架把评估器变成了机械的。**

这正是为什么整个设计把**全部**正确性都押在「铁砧必须非 LLM」上，而把提议者的弱点仅仅当作迭代次数的问题。

## 五条不变量

这是架构**定律**，不是偏好。打破任何一条，就变成了另一个框架。

1. **铁砧永远是机械的，绝不用 LLM。** 执行器、证明检查器、或保留数据匹配。任何让 LLM 当裁判的地方，都会重新打开自我确认循环。
2. **晶体双用途：蒸馏求流畅，调用求尾部。** 把程序蒸馏回权重会丢失分布尾部；让晶体在推理时保持可调用，尾部才能存活。
3. **晶体是「重采样器」，不是「记忆」。** 每个已验证程序都是一个生成器——它能按需无限重采样合法的输入输出。对抗有限样本熵衰减的真正机制是这个，而不是蒸馏。
4. **引导者有两份工作：**(i) 拒绝「验证通过但毫无用处」的平凡程序；(ii) 审计**规范接地**——「这个测试是来自现实，还是来自模型的先验？」
5. **选择信号是描述长度（MDL），不是模型似然。** `L = L(data|program) + L(program)`。这是那个非循环的排序信号。

之上还有一个**元循环**：规范/测试本身也是可证伪的程序，以同样方式递归接地。一个规范能存活，仅当其认证的程序持续预测现实。这就是回答「谁来验证验证器」无限回溯的方式。

## 这个仓库是什么

- 一个**研究框架和可证伪的假设**，不是生产系统。目前没有发布模型。
- 一个精确的**最小可行实验**规格（见 [`docs/experiment-design.zh-CN.md`](docs/experiment-design.zh-CN.md)），其职责是**证伪**这个框架，而非赞美它。
- 一份**失败模式**与**理论依据**的目录（见 [`docs/core-mechanism.zh-CN.md`](docs/core-mechanism.zh-CN.md)），让新读者看清这个设计到底要抵御哪一种坍缩、以及为什么。
